# 部署与运营注意事项

- 适用版本：OPC-site v40（2026-11-12）
- 适用读者：首次部署者、服务器运维、站点运营管理员
- 配套文档：[用户使用手册](./用户使用手册.md)

## 1. 先确认三件事

### 1.1 飞书账号：必须是企业/团队租户

工作台扫码登录依赖**飞书企业自建应用**。请先确认：

- 账号属于某个企业/团队租户，不是个人版账号；
- 在该租户的飞书开放平台能创建「企业自建应用」；
- 应用已发布/启用，网页授权已开启；
- 管理员 `open_id` 在应用可见范围内，并已加入 `ADMIN_OPEN_IDS`。

个人账号、未加入企业租户的账号，常见结果是：

- 扫码页显示“当前账号无法使用该应用”；
- 授权后工作台提示“该飞书账号没有工作台权限”；
- 服务端报 `21001 Access denied due to platform policy`。

这不是前端按钮问题，也不是改代码能绕过的问题。临时可用账号密码入口；长期应让企业管理员把你加入租户、应用可见范围和 Base 协作者。

### 1.2 多维表格：不会自动创建

**当前版本不会自动创建 Base，也不会自动创建 12 张表。**

首次部署前需要准备：

1. 一个飞书多维表格 Base；
2. Base 中包含 12 张表，表名必须与代码一致：
   `site_config`、`home_blocks`、`solutions`、`articles`、`products`、`shares`、`pages`、`method_faq`、`about`、`theme`、`samples_testimonials`、`audit_log`；
3. 字段与类型按 [12表字段清单.csv](./12表字段清单.csv) 配置；
4. 把飞书应用加入该 Base 的「文档应用」，否则发布会报 `TABLE_NOT_FOUND` 或权限错误。

> 工作台初始化向导里的“逐张核对 / 自动补齐缺失表”是**界面演示**，不会真正调用飞书建表接口。不要把它当成“已经建好表”。以实际发布结果和 Base 里的表为准。

推荐做法：复制一份已经配置好的模板 Base，再改 `BITABLE_APP_TOKEN`。手工新建 12 表耗时且容易漏字段。

### 1.3 回调地址：正式环境用 HTTPS 域名

飞书网页授权要求回调地址可访问且与后台登记一致。正式环境建议：

```text
https://你的域名/api/auth/callback
```

同时改 `.env`：

```ini
PUBLIC_GATEWAY_ORIGIN=https://你的域名
PUBLIC_ADMIN_ORIGIN=https://你的域名
FEISHU_REDIRECT_URI=https://你的域名/api/auth/callback
COOKIE_SECURE=true
```

`http://服务器IP:8081` 只适合内网/自检；飞书通常不允许把公网 HTTP IP 作为正式回调。

## 2. 部署步骤

### 2.1 服务器

- Ubuntu 22.04 / 24.04 或 Debian 12；
- 2 vCPU / 2 GB 内存 / 20 GB 磁盘起步；
- 安全组放行 `8080`（访客站）和 `8081`（工作台）；
- `8787` 是容器内网关端口，**不要**暴露公网。

### 2.2 拉取与安装

```bash
git clone https://github.com/HugoWorld/OPC-site.git
cd OPC-site
bash install.sh
```

只想先看访客站、不接飞书：

```bash
bash install.sh --demo
```

演示模式不校验飞书凭据，数据只写本机 `data/`，不写 Base。

### 2.3 配置 `.env`

```bash
cp .env.example .env
nano .env
chmod 600 .env
```

最少要填：

| 变量 | 说明 |
|---|---|
| `FEISHU_APP_ID` | 企业自建应用 App ID |
| `FEISHU_APP_SECRET` | 应用 App Secret，只放服务器 |
| `BITABLE_APP_TOKEN` | Base URL 中 `/base/` 后那段 |
| `ADMIN_OPEN_IDS` | 允许登录的管理员 open_id，逗号分隔 |
| `SESSION_SECRET` | 随机会话密钥，至少 32 字符 |
| `HUGOW_DEMO=0` | 关闭演示模式 |

可选但重要：

| 变量 | 说明 |
|---|---|
| `FEISHU_BASE_SYNC=required` | 12 表必须全成才切换快照；首次可临时 `best-effort` |
| `ADMIN_LOGIN_USER` / `ADMIN_LOGIN_PASSWORD` | 账号密码备用入口；密码至少 10 位，留空则关闭 |
| `ADMIN_DISPLAY_NAME` | 工作台显示名，避免暴露飞书昵称 |
| `ADMIN_BOOTSTRAP_TOKEN` | 临时运维令牌；OAuth 正常后必须置空 |
| `COOKIE_SECURE` | HTTPS 为 `true`，本地 HTTP 为 `false` |

> 不要把真实 `.env`、App Secret、Base access token、管理员密码、open_id 白名单提交到 Git。仓库只保留 `.env.example` 占位符。

### 2.4 启动与检查

```bash
./hugow status
./hugow logs
curl -I http://127.0.0.1:8080/
curl -I http://127.0.0.1:8081/api/health
```

健康检查返回 200、访客站能打开、工作台能登录，才算部署完成。

## 3. 飞书应用配置清单

在飞书开放平台：

1. 创建「企业自建应用」；
2. 记下 App ID / App Secret；
3. 开启网页授权，添加重定向 URL；
4. 申请/确认用户身份权限 `auth:user.id:read`；
5. 发布应用版本；
6. 在「应用可见范围」加入管理员；
7. 把应用加入 Base 的文档应用；
8. 在 Base 里确认 12 张表名与字段。

扫码登录失败时按顺序排查：

| 现象 | 检查 |
|---|---|
| 二维码打不开 / 4401 | 应用网页授权是否开启；授权地址是否过期 |
| 扫码后“无权限” | `ADMIN_OPEN_IDS` 是否包含你的 open_id；应用可见范围是否包含你 |
| `20029` | 飞书后台回调、`.env` 回调、实际访问域名是否完全一致 |
| `21001` | 账号是否企业租户；应用是否被平台策略限制 |
| 登录后立即掉线 | `COOKIE_SECURE` 与协议是否匹配；反向代理是否透传 Cookie |

## 4. 运营配置注意事项

### 4.1 账号

- 扫码是主入口，账号密码是备用入口；
- `ADMIN_LOGIN_USER` 默认是 `admin`，这只是用户名，不是个人账号；
- 密码由 `install.sh` 生成或手工设置，至少 10 位；
- 换管理员时：改 `ADMIN_OPEN_IDS`、改密码、重启，并让旧管理员退出；
- `ADMIN_BOOTSTRAP_TOKEN` 只用于 OAuth 尚未就绪的临时运维，正常后置空。

### 4.2 发布

- 工作台改动先进入浏览器草稿，点发布才写 Base 并生成本机快照；
- 发布失败不会切换当前快照，访客继续看上一版；
- 发布前确认 Base 可写、12 表齐全；
- 大改前先 `./hugow backup`，并导出 YAML/TS 留档；
- 站点内容与图片 data URL 可能在导出文件中，导出文件不要公开分享。

### 4.3 备份与升级

```bash
./hugow backup
./hugow upgrade
./hugow status
```

- 备份包含 `data/` 快照，定期做并异地保存；
- 升级前先备份；
- 升级后检查 `/api/health`、访客站、工作台登录、一次发布。

### 4.4 端口与反向代理

- 8080/8081 是容器内 Nginx 对外端口；
- 8787 只监听 `127.0.0.1`，公网不要开放；
- 上 HTTPS 时，Nginx/云负载均衡终止 TLS，应用侧把 `COOKIE_SECURE=true`；
- 反向代理必须正确传递 `Host`、`X-Forwarded-Proto`，否则回调/ Cookie 会异常。

### 4.5 内容与隐私

- `ADMIN_DISPLAY_NAME` 控制工作台显示名；
- 界面只显示 `open_id` 尾号，不展示完整标识；
- 访客站的联系方式、案例、证言由运营者自行确认是否公开；
- 公开仓库、截图、演示环境不要出现真实手机号、邮箱、open_id、App Secret。

## 5. 上线前检查清单

- [ ] 飞书账号是企业/团队租户，应用已发布并开启网页授权
- [ ] 回调地址与访问域名一致，HTTPS 生效
- [ ] `ADMIN_OPEN_IDS` 包含管理员，应用可见范围包含管理员
- [ ] Base 中 12 张表齐全，表名与字段清单一致
- [ ] 飞书应用已加入 Base 文档应用
- [ ] `.env` 权限 600，未被 `git status` 列出
- [ ] `HUGOW_DEMO=0`，`FEISHU_BASE_SYNC=required`（或明确使用 best-effort）
- [ ] 8080/8081 可访问，8787 未暴露
- [ ] 扫码登录成功；账号密码备用入口可用
- [ ] 改一处文案 → 发布 → 访客站生效
- [ ] 发布失败时访客站仍显示上一版
- [ ] 已执行一次 `./hugow backup`

## 6. 常见错误

| 错误 | 含义 | 处理 |
|---|---|---|
| `TABLE_NOT_FOUND` | Base 缺表或表名不一致 | 核对 12 个英文表名；应用加入 Base |
| `21001` | 平台策略拒绝应用换 token | 企业租户/应用发布/平台策略；临时用密码登录 |
| `20029` | 回调地址不一致 | 三处统一 |
| `403 / 91403` | 应用无 Base 权限 | 把应用加入 Base 文档应用 |
| `502` | 容器未启动/端口未放行 | `./hugow status`、`./hugow logs`、安全组 |
| 发布后前台无变化 | 未发布/缓存/发布失败 | 确认发布成功；刷新；看日志 |
| 扫码无权限 | 白名单/可见范围 | 加 `ADMIN_OPEN_IDS`、加应用可见范围 |

## 7. 安全边界

- App Secret、Base access token、管理员密码只存在服务器 `.env`；
- `.env` 不进入 Git，权限 600；
- 网关只监听回环，公网只经 Nginx；
- 登录会话用 HttpOnly Cookie，工作台先服务端验证再渲染；
- 发布接口有管理员限流与单实例互斥；
- 发现凭据曾进入公开仓库/截图，立即更换 App Secret、管理员密码，并检查 Base 协作者。
