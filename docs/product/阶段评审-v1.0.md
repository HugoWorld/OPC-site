# 产品化与一键部署 · 阶段评审 v1.0

> 目的：把这次从「给持有人用的单机部署」升级为「面向 0 基础人群的标准产品」的过程，
> 按阶段记录**评价、遇到的问题、如何计划解决、谁做的决定**。
> 角色不是摆设：每个阶段至少有一个反对意见或风险检查，避免一路顺推。

## 0. 一句话结论

| 项 | 结论 |
|---|---|
| 产品定位 | 面向律师/顾问/独立职业者等**非 IT 个人品牌经营者**的个人 OPC 门户，卖点是「不碰服务器」 |
| 本版交付 | 一体化镜像 + `install.sh` + `hugow` + 自动发现 12 表 + 图例化 README |
| 本版不承诺 | 自动创建 12 张 Base 表；豆包云托管完整 Node 网关；正式域名/证书代购 |
| 验收口径 | 新机器 `git clone` 后一条命令，访客站/工作台/健康检查可访问 |

## 2. 分角色记录

### 2.1 决策者（产品负责人）

**评价**：这次不是加功能，而是换交付物。原来交付的是「部署方案 + 脚本」，用户仍要理解
Nginx、systemd、证书、端口；现在交付的应该是「一个能启动的产品」。

**做的决定**：

1. 默认路径改为 Docker 一体化，原生 systemd 降为进阶方案。
2. 保留「先跑通」的演示模式：没有飞书凭据也能看到访客站，避免第一次安装就失败。
3. 不把「自动建 12 表」塞进本版。它是真需求，但会和字段类型、主键、权限纠缠，属于下一阶段。
4. 不承诺「完全不需要飞书配置」。产品可以减少服务器知识，不能取消平台授权。

**反对意见（审核角色提出）**：如果安装脚本自动 `curl get.docker.com | sh`，在企业内网会被安全策略拦。
**处置**：保留 `--no-docker-install`，文档写明手动安装路径；自动安装只在默认路径发生。

### 2.2 思考者（架构）

**评价**：单容器是当前最低成本的一体化形态。把 Nginx、Node、静态产物、数据卷放在同一镜像，
用户只需要理解「一个容器、两个端口、一个 data 目录」。

**关键取舍**：

| 选项 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 单容器 Nginx + Node | 一条命令；端口少；无容器间网络 | 进程耦合；升级整容器 | 采用 |
| 两个容器 + compose 网络 | 解耦；可单独扩 | 用户要多理解一层网络 | 不采用 |
| 纯静态 + 外部网关 | 可托管到豆包 | 管理台/发布不可用 | 只作为预览形态 |

**风险**：容器内 Nginx 以 root 启动、Node 以 `hugow` 用户运行；如果 entrypoint 只用 `sh`，
`wait -n` 不存在，容器会起不来。已改为 bash，并在实现中明确「任一进程退出 → 容器退出」。

### 2.3 设计规划（体验）

**评价**：0 基础用户不需要「架构图」，需要「我现在在哪一步、下一步点什么」。
所以图例分两张：一张讲**部署后有什么**，一张讲**第一次只填 4 个值**。

**设计规则**：

- 首页只放 3 步，不先讲技术栈。
- 每个配置值都给「从哪里复制」，不只给变量名。
- 所有错误都翻译成「下一步做什么」，例如 `TABLE_NOT_FOUND` 直接提示检查表名/文档应用。
- 不在 README 首屏放「12 表字段」「OAuth 状态机」这类实现细节，放到开发者段落。

### 2.4 审核（质量/安全）

**评价**：产品化最容易出的问题不是功能，而是「看起来一键，实际到处埋雷」。本阶段重点审四类：

| 风险 | 检查 | 处置 |
|---|---|---|
| Secret 入库 | `.env` 是否被忽略 | `.gitignore` 增加 `.env` / `data` / `backups`，保留 `.env.example` |
| 端口暴露 | 网关是否公网可达 | 容器内只监听 `127.0.0.1:8787`，只暴露 8080/8081 |
| 复制 Base 串数据 | 表 ID 是否还指向原作者 | 表名发现优先；发现成功但缺表时不再回退内置 ID，直接报错 |
| 一键脚本失败无提示 | 健康检查/日志 | `install.sh` 60 次轮询，失败自动打最近 60 行日志 |
| 文档过度承诺 | 「零后台」「全自动」 | 明确写「仍需飞书 4 个值」「自动建表下一阶段」 |

### 2.5 实施（工程）

**已落地的改动**：

1. `src/server/feishu-bitable.ts`：新增 `listTables()`，分页读取 Base 表清单。
2. `src/server/feishu-publisher.ts`：新增 `resolveTableIds()`，按表名归一化匹配；
   显式 `FEISHU_TABLE_IDS_JSON` 优先；读取表清单失败才回退内置坐标；缺表返回 `TABLE_NOT_FOUND`。
3. `src/server/config.ts` + `gateway.ts`：新增 `HUGOW_DEMO` 演示模式；`/api/setup` 返回 `demoMode`。
4. `Dockerfile` / `compose.yaml` / `deploy/docker/*`：一体化镜像与容器内 Nginx。
5. `install.sh` / `hugow` / `.env.example`：安装、状态、日志、备份、升级。
6. `.github/workflows/*`：CI 补 `test:gateway-http`；新增 GHCR 镜像构建。
7. `README.md` + 两张图例 + `deploy/README.md`：面向 0 基础用户重写。
8. `install.sh`：`.env` 创建后立即 `chmod 600`，避免 App Secret / 会话密钥被同机其他用户读到。
9. `hugow upgrade`：按 `HUGOW_IMAGE` 自动区分「拉镜像」与「本地重建」，并支持 `--image` 强制拉取；
   避免用 `--image` 安装后升级又在本机重新编译。
10. `vite.config.ts` + `package.json`：新增 `build:doubao` 单包模式（`inlineDynamicImports`、CSS 不拆分、
   图片内联），专门用于豆包静态托管预览；正式部署仍走 `build:all` 多 chunk，不牺牲首屏缓存。

**自评**：代码层「按表名发现」是这次产品化的核心；没有它，仓库只是「HugoW 专用站」，
不能称为可复制产品。

## 4. 本版明确不做

- 自动创建 12 张 Base 表与 114 个字段（下一阶段，需处理主键/字段类型/权限）。
- 自动申请域名、证书、ICP 备案。
- 多租户、计费、账号体系。
- 把 Node 网关塞进纯静态托管。
