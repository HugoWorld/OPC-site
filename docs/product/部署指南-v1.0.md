# 部署指南 v1.0（0 基础版）

> 目标：不要求你懂 Linux、Nginx、Node、数据库。
> 你只需要一台云主机、一个飞书账号，按顺序复制命令。

## 一、先看你要准备什么

| 要准备 | 说明 | 大约耗时 |
|---|---|---|
| 一台 Linux 云主机 | Ubuntu 22.04/24.04 或 Debian 12；2 vCPU / 2 GB / 20 GB | 10 分钟购买 |
| 飞书账号 | 能创建「企业自建应用」和多维表格 | 已有 |
| 一个 12 表 Base | 复制模板或按字段清单建；当前版本不自建表 | 10 分钟 |
| 管理员 open_id | 只允许你本人登录工作台 | 2 分钟 |

> 还没有飞书配置也能先跑：`bash install.sh --demo`。访客站可看，工作台停在登录页，不写飞书数据。

## 二、部署（复制粘贴即可）

### 1. 登录服务器

云厂商控制台一般会给「远程连接」或 SSH 命令。用 root 登录。

### 2. 拉取项目

```bash
git clone https://github.com/HugoWorld/OPC-site.git
cd OPC-site
```

### 3. 执行安装

```bash
bash install.sh
```

会依次提示你填 4 个值；如果直接回车跳过，会自动进入演示模式。

演示模式下访客站可直接浏览；工作台登录页会出现「进入演示工作台」按钮，
点一下即可预览完整工作台，数据只写入本机 `data/`，不会写飞书。

也可以完全跳过交互：

```bash
bash install.sh --demo
```

### 4. 想跳过本机构建：直接用已发布的镜像

```bash
bash install.sh --image
```

镜像已经由 GitHub Actions 构建并公开在 GHCR：`ghcr.io/hugoworld/opc-site:latest`，
不需要 `docker login`。拉镜像通常比本机编译快，2C2G 机器更推荐。

### 5. 看到这些输出就是成功

```
5/5 完成

访客站：   http://127.0.0.1:8080
工作台：   http://127.0.0.1:8081
健康检查： http://127.0.0.1:8081/api/health
```

把 `127.0.0.1` 换成服务器公网 IP，在浏览器打开：

- `http://服务器IP:8080` → 访客站
- `http://服务器IP:8081` → 工作台

> 如果打不开：去云厂商安全组放行 8080/8081；轻量应用服务器在「防火墙」页，CVM 在「安全组」入站规则。

## 三、接真实飞书登录

### 1. 创建企业自建应用

飞书开放平台 → 开发者后台 → 创建企业自建应用 → 记下：

- `App ID`
- `App Secret`

### 2. 配网页授权

在应用「安全设置」里添加重定向 URL：

```
https://你的域名/api/auth/callback
```

正式环境必须是 HTTPS 域名；`http://127.0.0.1` 只适合部署自检，飞书一般不允许作为正式回调。

### 3. 把应用加入 Base

打开你的多维表格 → 右上角「…」→ 添加文档应用 → 选择刚创建的应用。
否则应用读不到表，发布会报权限错误。

### 4. 填 `.env`

```bash
nano .env
```

改这几行（其余键见 `.env.example` 注释）：

```ini
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
BITABLE_APP_TOKEN=xxx
ADMIN_OPEN_IDS=ou_xxx
HUGOW_DEMO=0
# Base 同步：required=12 表全成才切快照；best-effort=Base 失败仍发站点；off=只发快照
FEISHU_BASE_SYNC=required
# 可选：直接注入 user_access_token / tenant_access_token，留空则用 App 身份换 token
FEISHU_BASE_ACCESS_TOKEN=
# 可选：OAuth 不可用时的管理员登录令牌；install.sh 会自动生成并打印
# 它不是给客户的授权码，只用于站点所有者登录工作台
ADMIN_BOOTSTRAP_TOKEN=
# 个人账号无企业租户、OAuth 授权页报“无法使用”时置 0，登录页改走管理员令牌
FEISHU_OAUTH_ENABLED=1
```

> 如果 `FEISHU_APP_ID` 对应的账号是**个人豆包账号、没有企业租户**，飞书会以
> `21001 Access denied due to platform policy` 拒绝 `tenant_access_token`。此时
> `required` 会让每次发布都失败；先把 `FEISHU_BASE_SYNC=best-effort` 保证站点能发，
> 再按 `docs/delivery/飞书应用21001诊断与处置-v1.0.md` 注册企业租户或注入用户 token。
>
> **管理员登录令牌不是客户授权码**：它只用于 OAuth 未启用时站点所有者登录工作台。
> 域名/HTTPS/飞书回调配好并启用 OAuth 后，把 `ADMIN_BOOTSTRAP_TOKEN` 置空即可下线该入口。

保存后重启：

```bash
./hugow restart
```

> `install.sh` 在真实登录模式下会按服务器公网 IP 自动填 `PUBLIC_*` 和
> `FEISHU_REDIRECT_URI`。绑定 HTTPS 域名后，这三项要一起改成域名。

### 5. 验证

```bash
./hugow status
```

`/api/health` 返回 200，工作台能用飞书登录，就通了。

## 四、日常只用网页

| 要做的事 | 去哪里 |
|---|---|
| 改首页/产品/文章 | 工作台左侧栏目，草稿 + 实时预览 |
| 让访客看到新内容 | 点「发布」 |
| 看发布是否成功 | 工作台发布页 / `./hugow status` |
| 备份 | `./hugow backup`（或加 cron） |
| 升级 | `./hugow upgrade`（镜像模式自动 pull；源码模式重建） |
| 看日志 | `./hugow logs` |

不需要登录服务器改内容，也不需要手动改数据库。

## 六、常见问题

**Q：`install.sh` 卡在安装 Docker**
A：服务器访问不了 `get.docker.com`。先手动装 Docker Engine + Compose，再执行 `bash install.sh --no-docker-install`。

**Q：`docker compose pull` 一直停在 `Pulling fs layer`**
A：国内网络到 GHCR 的镜像层可能被阻断。改用源码模式 `bash install.sh --demo --no-docker-install` 在本机构建；Dockerfile 已把 Debian apt 源切到 `mirrors.tencentyun.com`。基础镜像拉取慢时，给 Docker 配 `registry-mirrors: ["https://mirror.ccs.tencentyun.com"]` 后重启 Docker。

**Q：8080/8081 被占用**
A：改 `.env` 的 `HUGOW_WWW_PORT` / `HUGOW_ADMIN_PORT`，再 `./hugow restart`。

**Q：登录报 `20029`**
A：飞书后台的重定向 URL、`.env` 的 `FEISHU_REDIRECT_URI`、实际访问域名三处必须完全一致。

**Q：登录报 `21001`**
A：飞书平台策略拒绝应用换 token，需开放平台侧处理；不是本项目的代码问题。

**Q：发布报 `TABLE_NOT_FOUND`**
A：Base 缺表或表名不一致。核对 12 个英文表名；确认应用已加入 Base 文档应用。

**Q：发布失败，访客站会变空吗**
A：不会。失败时不切换 `current.json`，访客继续看上一份完整快照。

## 七、还没有服务器，怎么先看

当前版本的一体化镜像需要 Docker。没有服务器时，可以：

1. 用开发预览：`cd prototype && npm run dev`，打开 `http://localhost:5173/`；
2. 或在任意支持 Docker 的机器上 `bash install.sh --image`（镜像已公开发布）；
3. 或先看豆包静态预览（仅访客站，不含登录/发布），评估见 `阶段评审-v1.0.md` S5。

> 不建议把 `npm run dev` 当成正式部署：它是开发服务器，不适合公网长期运行。
